# The local secret store is an in-memory development instance, seeded by script

Database credentials must not live in this repository, so they live in HashiCorp Vault, and the only Vault available locally is a development-mode container owned by another project: it holds everything in memory, both of its volumes are empty, its intended file-storage configuration is never loaded, and its administrative token is a public placeholder baked into that project's image. Repairing its durability was considered and rejected, because it would mean recreating a container this work does not own, reconfiguring another project's stack, and managing real unseal keys outside the repository, all for a laptop secret store whose only consumer is a throwaway cluster. Instead the instance is reused as what it is and the loss is made explicit: an idempotent seed script restores the credentials, mints a periodic token scoped to this project's path prefix, and is documented as the step to run after any restart. The consequence is stated rather than hidden: restarting the store erases its contents, and a missing credential there is a reason to re-run the seed script, not to debug the synchronisation controller.
