# Local cluster runs on kind, pinned to Kubernetes 1.36

The repository needs a local Kubernetes cluster that predicts how charts behave on the managed service, on a Windows laptop, without a second toolchain. We chose kind 0.33.0 with the node image for Kubernetes 1.36.4 pinned by digest: kind runs upstream Kubernetes rather than a repackaging, it gives a real multi-node topology so scheduling behaviour is not flattened, and it pins the exact version through the node image. 1.36 is the version new managed clusters default to and sits inside the support window of every component this repository installs, while 1.34 leaves support this month and the newest minor is outside the supported range of several of them. The alternatives were rejected for concrete reasons: Docker Desktop's built-in Kubernetes is single-node and opaque, minikube trades upstream fidelity for convenience, and k3d was not installed and offered nothing kind did not.
