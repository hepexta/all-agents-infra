# The cluster serves two ingress contracts, with three controllers

Charts written for the managed service today emit classic Ingress objects under the application routing class name, while the managed service is visibly moving to Gateway API, and the transport-layer routing the database needs exists only in the gateway contract. Serving both is therefore not redundancy but a deliberate refusal to pick a side: the standard ports are given to the classic contract because that is what people's charts and muscle memory assume, and the gateway contract gets its own ports because a node port can be claimed by exactly one service. Two consequences are recorded rather than discovered later. Mirroring the managed service's class name costs a whole extra controller installation, because a controller handles exactly one class, and the second one is marked as the cluster default so that an Ingress naming no class is still served. And transport-layer routing requires the experimental custom resources plus a feature flag, which the managed service would not install, so nothing may come to depend on it silently.
